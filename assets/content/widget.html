Add prayer times and announcements to your masjid website using the widget editor in the Masjidal portal. Customize the appearance, publish your settings, and copy the embed code for each widget.

Professional plan

Extra colors and theme options require the Professional plan. The options available in your account depend on your plan.

Announcements eligibility: the current widget library displays the Announcements widget only when its saved settings mark the account as premium-enabled. If prayer times work but announcements stay completely blank, ask support to check the account's widget entitlement.

1. Open the widget editor

  1. Sign in to your Masjidal portal and select the correct masjid.
  2. In the left menu, open Integrations → Widgets.
  3. The editor shows previews for Prayer Times and Announcements. Use Installation Guide for the installation steps.

2. Allow your website domain on the frontend key

Required before the widget can load.

Adding the script and embed code is not enough if your website is not allowed by the frontend key. The API can return 403: Origin not allowed for this API key, while the widget itself stays completely blank.

  1. In the Masjidal portal, open Integrations → API Keys.
  2. Find the frontend key used by your widget embed. It begins with msj_pk_. Make sure you are editing the key shown in your own masjid's embed code.
  3. Edit its allowed website domains. Add the actual hostname where visitors will load the widget, for example isaugusta.com. If you use a www address or a staging subdomain, check whether that hostname also needs to be added.
  4. For the example page linked below, add sgumerrabbani.github.io. This allows the GitHub preview; it does not replace the permission for your own website.
  5. Save the API-key changes, then continue with the library and embed steps.

Use the website hostname, rather than a page path such as /prayer-times/. Test on the published website. A local HTML file or a page-builder preview may use a different origin from the public page.

Open the working new-widget example. It uses a separate configured masjid account. Copy your own portal embed for your masjid's timings and announcements.

3. Add the widget library to your website

The new embed needs two parts.

An older iframe widget loads its own page. The new <masjidal-widget> tag needs the library script below as well as the embed snippet. Pasting only the widget tag into a Raw HTML block will not display anything unless the library is already installed on that page. The async attribute on the widget tag does not load the library.

Add this script once inside your website’s <head> tag, on the pages where the widgets will appear:

<script
  async
  src="https://widgets.masjidal.com/timetable/v0/widget.js">
</script>

This loads the widget library. You will add the individual widget snippets where you want the prayer times or announcements to appear.

4. Customize the widgets

Global appearance

  • Dark Mode: choose Light, Auto, or Dark.
  • Accent Color: select an available color. Extra colors and theme options require the Professional plan.

Prayer times

  • Layout: choose from the options available for your plan. The editor shows Grid, Table, Table 2, Ribbon, Compact, and Minimal Bar.
  • Header: select Masjid Name, Prayer Timings, or Hide.
  • Hijri Date Changes At: choose Midnight or Maghrib.

Announcements

Choose an available layout: Stacked, Compact, or Ribbon. Check the preview to see how your announcements will look.

Open Advanced Settings if you need to adjust the additional controls available in your account.

5. Publish your settings

When you are happy with both previews, click Publish at the bottom of the settings panel to save the widget configuration. Install the library and publish your settings before embedding the widgets.

6. Embed prayer times or announcements

  1. Click Embed above the Prayer Times or Announcements preview.
  2. The portal fills in your frontend key automatically. Manage your keys and allowed website domains under Integrations → API Keys.
  3. Click Copy and paste the complete snippet into your website’s HTML where you want the widget to appear.
  4. For both widgets, copy and place each snippet separately. Load the library script only once on the page.

Prayer times example

Copy widget IDs and keys exactly from the portal, without extra spaces at the beginning or end of the quoted values. Test the published page; the page builder's editing canvas may not run third-party widgets.

These examples use placeholders. Copy your own complete snippet from the portal instead of using these values.

<masjidal-widget
  async
  widget-id="YOUR_WIDGET_ID"
  type="prayer"
  api-key="YOUR_FRONTEND_KEY">
</masjidal-widget>

Announcements example

<masjidal-widget
  async
  widget-id="YOUR_WIDGET_ID"
  type="announcement"
  api-key="YOUR_FRONTEND_KEY">
</masjidal-widget>
Use a frontend key

Website widgets use a frontend key beginning with msj_pk_. Add the actual website hostname to its allowed domains in API Keys. Check the address visitors use, including any www or staging subdomain; do not assume a different hostname is covered. Never put a server key beginning with msj_sk_ in website HTML or browser JavaScript.

Installing on WordPress

  1. Add the library script to the site’s head using your theme’s supported integration field or an approved header-code tool. If the page uses Divi, its Theme Options → Integration area may provide a head-code field.
  2. Edit the page and add a Custom HTML block, or a Code module in Divi.
  3. Paste the actual widget snippet copied from the portal into that block or module.
  4. Save the page, clear any page cache, and check the published page on a phone and a desktop.

Your WordPress account must be allowed to save custom HTML and scripts. If your editor removes the code, ask your site administrator to install it through the site’s supported code-insertion method.

If a performance plugin delays JavaScript until a visitor clicks or scrolls, the widget may not start immediately. For WP Rocket, check File Optimization → Delay JavaScript execution and exclude widgets.masjidal.com/timetable/v0/widget.js from that delay when troubleshooting. Save, clear caches, and retest the published page while logged out.

If a widget does not display

A blank area does not identify the cause.

The current library can return an empty widget without a visible error when the settings request fails or returns no saved settings. The prayer widget also remains empty when no timing entries are returned. Use the checks below to find which part failed.

  1. Check the published page. Use the actual website address, rather than only the editor preview or a local HTML file. Confirm that the snippet is saved in a Custom HTML block or Code module.
  2. Check the library. Confirm https://widgets.masjidal.com/timetable/v0/widget.js loads and runs. Its download alone is not enough: the widget also needs API requests to succeed.
  3. Check the complete snippet. Copy it again from the portal after publishing. Replace every example placeholder. Keep the exact type: prayer or announcement (singular).
  4. Check the frontend key and allowed hostname. Confirm the key is active and belongs to the correct masjid, and check the actual hostname visitors use under Integrations → API Keys.
  5. Check the settings were published. Return to Integrations → Widgets, click Publish, and copy the current embed code. If the API still returns no settings, ask support to check the widget ID and saved configuration.
  6. Check the requested content exists. Verify Salah timings are available for the current dates. For an entirely blank Announcements widget, also check premium eligibility.
  7. Check site restrictions and optimization. Script blockers, consent tools, delayed JavaScript, or your site's security policy can block the library or its API requests. Have your site administrator identify the blocked request before changing those settings.
  8. Clear caches and reload the published page after correcting the identified issue.

Find the failed request

For a technical check in Chrome or Firefox: open the affected page, press F12 (or open Developer Tools from the browser menu), select Network, and reload the page. Filter for masjidal. Check the following requests:

RequestWhat to look forWhat it means
widgets.masjidal.com/.../widget.jsLoads successfully and is not blocked or delayedWithout the library, the custom widget tag cannot display anything.
api.masjidal.com/widgets?widget_id=...A successful response containing data.settingsA failed request or missing settings keeps the whole widget blank.
api.masjidal.com/timings?...For prayer times, a successful response with a non-empty data.timings listA failed request or empty timing list leaves the prayer widget blank.
api.masjidal.com/announcementsFor announcements, inspect both this response and data.settings.isPremium from the settings requestAnnouncements are rendered only when premium-enabled. With an eligible account, an empty list normally shows a no-announcements message rather than an entirely blank area.

401 or 403: read the response message and have support check key validity, permissions, allowed domain, and widget access. 500-class errors: send the failing request and status to support for a service-side check. CORS, CSP, or blocked-request errors: inspect the browser Console with your site administrator. A successful HTTP status alone is not enough if the expected settings or timing data are missing.

Page builders and dynamically inserted widgets

The current library reads the widget ID, key, and type when the widget element is first attached to the page. A builder that inserts an empty tag and adds its attributes later can leave it blank, even if the attributes look correct when you inspect the page afterward. Use the complete static snippet in a Code/Custom HTML module and test the published page. If only a dynamic preview fails, ask your developer to check how the element is inserted.

When asking support for help, send the public page URL, which widget is affected, the failing request/status or response message, and whether it fails on the published page or only in the editor. Never send a server/private key. Avoid sharing unredacted browser network logs, which may contain credentials or other account data.
